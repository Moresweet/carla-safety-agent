# 逐对象位置撤销 / 重做

Scene Object Manager 的“位置撤销 / 重做”只修改当前对象，不恢复整场景或删除其他对象。新`/objects/update-reviewed`位置提交在空闲世界中为本工作台纳管的user对象自动记录完整位置/旋转；旧内部更新接口、闭环编辑、复制、删除、纹理绘制不自动纳入。

历史绑定episode字符串、actor ID、type ID和稳定ID，桥接重启保留；换图或重新生成的新运行时对象不会自动继承旧历史。整场景跨图恢复及纹理版本仍使用原有独立功能。

## 持久化与故障边界

- `data/transform-history/<identity-sha256>/current.json`保存最多1000条链及游标，读取最多4MiB，检查身份、完整位姿、链连续性、唯一条目、游标及未完成意图。损坏/链接文件不按空历史处理。
- 原生移动前写入意图；只发送一次set_transform，之后最多5秒/128次观察，要求两个不同的连续快照处于目标容差内。迟到旧快照不立即误报失败，也不触发重发。
- 不明确的原生结果或桥接中断保留待检查记录，阻止该运行时对象进一步记录/重放位置操作。不会自动回滚、补执行或根据当前坐标猜测历史已完成。
- 显式检查会归档旧记录并开始空链，不移动对象、不宣称前次操作成功。撤销后另做修改保留旧分支归档；外部位置变化使旧历史重放拒绝，之后的新位置提交另起链。
- 使用原子文件替换与目录同步，不是引擎/文件系统事务或所有断电保证。写入发布之后同步返回错误时需检查实际文件，不盲目覆盖已完成记录。协调范围是单桥接进程和仿真锁，不是所有外部CLI/原生工具的跨进程锁。
- 不改变其他对象；不是全部编辑操作的统一撤销栈，不自动迁移运行时历史到其他机器。归档与失败证据不自动删除。

## 接口

- `GET /objects/transform-history?actor_id=...`：是否适用、当前观察、修订号、撤销/重做数量、待检查意图及游标附近最多10项；闭环执行时明确不适用。
- `POST /objects/transform-history`：`action`为undo/redo/acknowledge，包含最新`revision`、当前观察`expected`和严格`confirmed:true`；acknowledge另带`intent_id`。旧修订与旧对象观察拒绝，不自动重试。
