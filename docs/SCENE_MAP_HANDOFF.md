# 显式跨地图场景恢复

“项目与场景版本”中的普通恢复仍是同地图合并。新增独立“跨地图恢复”区：选择本地场景当前版本 → 预检 → 检查源/目标地图与对象数量 → 勾选销毁当前运行世界的确认 → 保存工作台备份 → 后台加载地图并恢复目标版本。

地图切换会销毁整个旧运行世界，不是同地图合并。备份只涵盖工作台纳管的稳定对象、受支持纹理、环境材质/可见性、天气和视角，不包括物理历史、外部控制器状态或任意第三方编辑。

## 保护与失败边界

- 预检要求没有活动模型/采集、批量调度、原生资产导入、同步世界或传感器；源世界中未纳管车辆/行人/道具以及外部控制器拒绝切图。纳管对象清单必须能形成一致的保存快照。
- 明确选择 scene ID 和 version；120 秒单次确认绑定目标文档、源 episode（字符串保存 uint64）、纳管状态及动态对象清单。确认前改变目标或当前世界需重新预览。
- 兼容 CARLA 返回短地图名或完整包路径，精确匹配而非 Town05 前缀猜测；加载后重新验证真实地图与新 episode。目标材质槽/生成网格的最终兼容性仍需在加载后验证。
- 在破坏性 RPC 前原子写入切图意图，先保存工作台备份；普通编辑和模型启动被阻止。已在等待的旧 episode 编辑请求也会被拒绝，不能在新地图上继续作用于旧 actor ID。
- `data/scene-handoffs/current.json` 为当前门控记录；开始下一次操作前保存前次终态到 `<request-id>.json`。状态损坏或路径链接拒绝当作空闲；桥接重启后未结束操作显示 `needs_attention`，不自动继续或回切。
- 加载超时可能表示世界已改变；加载后恢复失败也不会自动重载旧地图。此时保留备份和错误，普通世界操作继续阻止。
- 用户需先检查原生窗口、备份和错误，再显式“接受当前世界”。后台要求无活动任务/传感器并观察连续空闲状态，然后只解除阻止，不补做恢复或删除对象，不将故障标记为恢复成功。可选择备份，再另行确认恢复。
- 常规维护脚本会拒绝运行中或待检查的切图；已证明原生服务退出的专用崩溃重启模式仍保留原生/进程检查，不清除切图记录。
- 后台工作运行在桥接拥有的线程，并非独立引擎事务。不能防护所有外部 CLI/Unreal 同时写入、恶意本机文件替换、所有断电或原生崩溃；异常后的真实世界仍需检查。
- 当前入口针对本地 SceneStore 版本。项目 ZIP 的直接恢复仍采用原有同地图流程；自生成 OpenDRIVE 地图若不在已安装地图清单中，不通过此入口伪造可恢复性。

## API

- `POST /scenes/handoff/preview`：`scene_id`、`version`；无换图。
- `POST /scenes/handoff/confirm`：`review_token`、严格布尔 `confirmed: true`；单次确认，返回后台记录。
- `GET /scenes/handoff`：只读当前记录，不触发恢复。
- `POST /scenes/handoff/acknowledge`：`request_id`、严格布尔 `confirmed: true`；只处理已经停止的待检查操作。
