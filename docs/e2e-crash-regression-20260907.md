# 2026-09-07 闭环启动崩溃排查

## 已知证据与限制

- 原始 UE 日志及桥接、评测日志保存在 `.runtime/crash-20260907/`。
- 原始崩溃是 UE 原生 SIGSEGV，而非 VAD 的 Python 异常。提供的栈只有信号处理函数，不能据此确定具体 C++ 故障位置。
- 原始日志在崩溃前未记录新的 LoadMap；评测日志尚未到达 `load_world success`。因此尚无证据将这次崩溃直接归因于地图切换。
- `Sensor 1 '' created in primary server` 来自 `get_sensor_token`，不能把每一条都解读为创建了一台摄像机。旧桥接每次请求都创建新的 CARLA Client，会导致重复订阅世界流。

## 修复

- 复用桥接 CARLA Client；编辑器操作与闭环启动共享交接锁。
- 评测初始化没有状态快照时返回明确的 initializing 状态，不再回退到直接访问 CARLA。
- 评测运行时阻止编辑器直接 RPC，支持的操作仍通过评测内命令队列执行。
- 交接前停止编辑器追车；预览生成、编辑器操作、追车单步均纳入交接锁。
- 启动前检查 CARLA 是否可访问，避免向已崩溃的服务启动长时间等待的模型进程。
- 拒绝重复启动；停止请求幂等，避免第二次 SIGINT 中断资源清理。
- 每次预设测试使用独立结果文件；用户主动停止标记 stopped；环境检查不再要求存在路线报告。
- 前端立即锁定请求，显示接口错误，运行时锁定模型/路线选择，并同步当前任务的模型与路线。
- 只支持 UniAD-Tiny 的生成场景/单独加载入口不再冒充其他选中模型。

1. 在可视化 CARLA 和浏览器中启动 VAD 默认 Town12 / #1711。
2. `tools/regression_e2e.py` 检查六路图像、轨迹、三次聚焦、纹理替换及至少 60 秒持续运行。
3. `tools/regression_e2e_lifecycle.py` 通过真实服务顺序运行模型，检查重复请求拒绝、推理帧前进、图像可解码、停止退出和编辑器恢复。
4. Python 回归测试及前端 TypeScript 检查。

附加保护：模型在初始化过程中被取消时，由桥接在模型进程退出之后恢复异步仿真，防止未进入评测自身清理代码就退出而留下冻结世界。

边界测试另外发现并修复了初始化取消失效：后台 shell 的 SIGINT 忽略状态可能被继承；上游 handler 在初始化阶段只清除 `_running`，后续启动又设回 True。项目现在使用取消安全启动器，提前恢复信号处理，初始化取消直接中断，正常运行取消仍走上游清理。最终复测在启动后第 5 秒连续停止两次，约第 5.3 秒返回 stopped（退出码 130），`cleanup_error: null`，编辑器可访问。先前失败试验不计为通过。

这些是功能与稳定性回归，不是完整路线驾驶得分评测。主动停止的路线不可声称完成，不代表模型驾驶能力达标，也不能保证所有地图、路线和长期运行绝不出现引擎故障。
