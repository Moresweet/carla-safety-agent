# 全 runtime 容量管理：盘点基础

## 歧义清单不执行回收

预览JSON解析现拒绝重复键（含嵌套对象）及NaN/Infinity常量，防止重复generation字段被静默覆盖后错误选择保护帧。新增三种歧义清单测试均保留四个代目录和原清单。缓存与采集相关79项通过（41.08秒）。这是对自动删除前提的加固，不是新增真实数据删除；最新解析逻辑尚未做原生采集回归。

## 预览清单受限读取

latest.json的初始读取和删除前复核均改用O_NOFOLLOW/O_NONBLOCK打开、fstat普通文件验证及8 MiB大小上限，避免FIFO等待写者或异常文件无限读取拖住采集tick。新增FIFO与稀疏超限清单测试，两者均在删除前拒绝、四个预览目录及内容完整保留；缓存相关20项通过（0.11秒）。这是受控文件测试，未对运行中的真实清单做破坏性注入，也不解决非协作外部目录替换竞态。

## 回收参数拒绝非有限值

提交前审核发现grace_seconds/now原先未严格检查NaN、Infinity和布尔值，异常比较可能绕过保护窗口。现先验证类型、有限性及非负值；非法参数在读取和删除前拒绝。新增11种异常参数测试，验证所有缓存文件字节不变；预览模块18项测试通过（0.10秒）。未删除实际缓存，也未以测试通过声称全runtime硬配额已完成。预览集成测试依赖尚未提交的采集/配额改动，本模块本轮暂未单独提交，避免形成不可独立运行的测试提交。

## 重复扫描准入保护

全runtime端点新增进程内非阻塞扫描锁：同一桥接多个页面同时请求时，后来的请求返回409/runtime_storage_busy，不排队重复扫描。前端给出明确手动重试提示，不自动重放请求。真实线程测试覆盖扫描进行中拒绝第二请求、扫描异常后释放锁；7项容量专项和类型检查通过。正式桥接重载为1358340后，真实HTTP并发验证得到409与200，随后再次扫描成功，路径覆盖请求被拒绝；收据 runs/validation/runtime-storage-http-20260929.json 的 passed=true。本锁不是跨进程或与录制盘点共享的全局锁。

## 跨会话保留窗口自动化边界

新增真实临时文件系统测试：模拟50次会话、每10秒产生3帧且帧号随重启下降，共150个代目录。每轮保护latest引用；60秒读者缓冲内观测峰值18个目录，缓冲到期后收敛为6个。另测实际SensorCapture.process调度在100/160/220秒才扫描，其他tick不触发全目录扫描。7项缓存专项通过。

这里使用受控时钟和临时文件，不称为50次原生引擎重启。峰值18只对应给定发布频率；未知文件不自动删除，因此该策略不能宣称任意输入下的硬容量上界。

`evaluation-control/capture/frames`占约8.5GiB，是主要来源。`SensorCapture.__init__`每次将live_generations重置为空；process_frame只将本次生成帧加入该列表并淘汰超过6项的本次帧。旧进程留下的目录不会加入列表，因此虽然单会话有6帧窗口，跨会话总量仍持续增长。

正式录制写入generated-scenarios，实时预览则先写capture/frames并原子更新latest.json。当前latest指向149145帧；不能简单按数字大小保留“最大6帧”，因为重启引擎后的帧号会降低（历史目录已有2150849）。修复须按当前manifest引用保护、验证预览文件类型、拒绝链接/未知内容，并在写入者互斥下回收；当前仅诊断，尚未删除这8.5GiB，也未声称泄漏已修复。
