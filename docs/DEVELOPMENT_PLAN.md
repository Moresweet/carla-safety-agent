# 本机自动驾驶场景编辑与测评平台开发计划

用户确认日期：2026-09-08。执行状态：进行中，所有阶段验收通过前不标记整体完成。

## 产品目标与约束

形成可追溯的闭环：创建场景 → 编辑资产/纹理 → 配置模型/传感器 → 测评与采集 → 回放诊断 → 修改再验证。
保持本机开发，不主动部署云端，不先做 Docker；保留现有代码、资产与历史数据。采用模块化后端和独立执行进程，不引入不必要的微服务。
用户要求逐步实现直到完成；实现、单测、实机验收分别记录。不能以静态占位或代理数据代替真实接入。

## 目标架构

1. 项目与资产：稳定对象 ID、资产版本、路径和依赖索引；正式数据与临时运行目录分离。
2. 场景编辑：保存加载、历史版本、撤销重做、自然语言计划、对象和材质编辑。
3. 仿真会话：单一 tick 所有者、状态机、后端冲突保护、停止恢复、健康检查。
4. 模型适配：统一生命周期/输入声明/控制输出接口，保留各模型真实输入差异。
5. 采集回放：有界缓冲、严格采集与性能测评模式、时间同步、标定、原始数据与预览隔离。
6. 实验报告：配置快照、模型权重校验、场景/资产版本、随机种子、失败原因和对比。

一级导航：项目总览、场景工作台、资产与材质、实验中心、数据与回放、分析与报告。
Blender 是资产制作后端；ROS 是外部订阅与可视化接口，不要求用户理解内部工具才能完成主流程。

## 流程与安全

- 自然语言先展示地图/对象/位置/触发器/依赖/不支持项，再执行；分别描述已有地图布置、新物体制作、新道路地图生成的能力。
- 材质编辑显示对象、材质槽、影响范围、UV 类型、草稿/已应用状态；不支持单实例修改时拒绝或明确选择共享范围。
- 启动前检查权重、环境、地图、显存、传感器、磁盘、任务冲突、资产依赖。
- 结果分成驾驶表现、执行状态、数据完整性、复现条件；区分碰撞、模型进程错误、CARLA 崩溃、采集错误。
- 保存不可变实验快照，记录软件版本与配置；固定种子不等于跨硬件绝对确定性。
- 重放数据不等于重演 CARLA 世界；顶视 RGB 不等于语义 BEV；预测轨迹不等于未来真值。
- 有界写盘：严格采集可减速仿真；性能模式单独测量推理时间，缺失必须记录。
