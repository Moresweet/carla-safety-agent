## 四条主链路及用户追加要求

| 功能包 | 必须交付的用户操作 | 本轮验收终点 |
|---|---|---|
| 场景与纹理 | 区分场景原有/用户新增对象；选择具体物体和材质槽；真实网格/UV预览；替换和恢复纹理；保存并重新打开场景 | 车辆、行人、建筑、道路、道具各完成一次选取→应用→实景查看→恢复；不支持资产列明原因，不能拿通用网格冒充真实UV；“任意元素”覆盖缺口仍记录，不虚报支持 |
| 模型测评 | 已接入端到端模型使用真实权重和真实输入；启动、查看画面、停止、展示结果；解决VAD点击开始崩溃 | 每个已公开可选模型完成一次启动→实际推理→停止；记录失败原因；不将算法碰撞等同于平台崩溃，不承诺任意工况永不崩溃 |
| 采集与播放 | 六视角RGB、深度、LiDAR、BEV、标定和轨迹；保留模型真实输入差异；保存录制、选择记录、播放暂停、跳帧；清楚的多视角/ROS布局 | 一次真实录制保存后重新打开，逐帧查看各通道和轨迹；六路大图有明确方位，深度与BEV点云可见 |
| 自然语言与Blender | 描述→生成计划→创建模型→Blender导出→Unreal导入→CARLA Blueprint注册→场景生成→视角聚焦；支持纹理修改 | 用一个新描述完成真实闭环并保存场景；现有地图布置与新道路地图生成区别明确；未支持的任意道路生成保留为真实缺口 |

共同交付：说明启动方式、实际可用功能和剩余缺口，保留关键截图；审核后分组提交。GitHub推送须处理此前明确拒绝，不绕过。迁移不依赖聊天记录，沿用仓库计划、启动脚本和项目包。

## 不作为本批结束前置条件

小时级/任意并发压力、全组合实验矩阵、跨所有操作的统一撤销栈、所有故障的事务回滚、未经证实的预测时间评分、跨机器引擎重建自动化。这些保留为后续工作，不能借此无休止推迟主功能交付，也不能反过来宣称已经完成。

## 数据清理

可重建日志、过期实时预览和重复调试录制可以按已确认目录清理，再运行受影响功能确认可再生；不为清理新增庞大的审计系统。不通过删除未知文件来猜测其作用。保留用户资产、模型权重及用户需要的正式采集数据；历史测试基线不必永久全量保留，只保留代表性可用样本和必要失败证据。

2026-10-13实查.runtime约93GiB，其中generated-scenarios约90GiB，主要是传感器录制而非文本日志。本轮尚未新增删除，不重复计入之前8.36GiB预览清理。

先交付“采集保存播放＋多视角布局”，再交付“场景来源＋真实UV纹理编辑”，随后完成“模型启停测评”和“自然语言Blender闭环”。各包以以上用户操作验收，不重复已经通过且代码未受影响的测试。遇到真实阻塞说明原因，不将小概率边界无限扩展为新任务。
