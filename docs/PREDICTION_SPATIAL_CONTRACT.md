# 预测轨迹：来源、参照点与复用

新采集保存实际控制器调用产生的规划输出、生成帧、模型step、世界时间和生成时自车位姿。只观察原本发生的control_pid调用，不额外运行推理或PID，不替换最终控制选择；异常也恢复原方法。TCP直接控制分支仍会计算规划分支，两者分别记录，不将规划线冒充最终采用的控制。

- ADMLP/model.py:57采用相同轴交换，SHA256为75c5474763d756f4d34f232076656b19ead52edf0ed6c9568848c539c4976e86。TCP与AD-MLP当前只展示控制器保存的四个点，不声称包含全部网络预测时域。
- B2D_e2e_dataset.py:505、B2D_vad_dataset.py:352的未来标签由相邻world2lidar变换构造，参照点是LiDAR，不是车中心。运行时agent.lidar2ego须匹配已审查标定，转CARLA车体偏移为(-0.39,0,1.84)m。预测与真实轨迹共同使用该参考点；真实参考点随各帧车体旋转，不能仅给车中心轨迹加常数偏移。
- TCP/data.py、ADMLP/data.py使用自车位置差与航向旋转；控制器记录转换后按ego heading平面解释。回放用预测生成时航向和位姿变换到当前车体坐标。

`tools/audit_controller_contract.py`不导入模型或权重，提取control_pid源码并规范末尾换行后计算指纹。新采集核对运行中真实方法源码指纹；变更/未知方法或标定拒绝套用旧坐标约定。这只是特定本机控制器契约，不是整个运行环境或模型文件完整性证明。

## 预热和旧预测

TCP首帧积累历史，没有规划输出；AD-MLP前21帧仅积累输入，之后每10帧更新预测。不能以一秒20帧的生命周期测试证明AD-MLP已推理。

PlanningObservation保留上次实际生成的输出与原始位姿；复用时不修改其生成帧。回放将旧预测从源位姿转换到当前位姿并显示年龄，避免车辆运动后旧线跟着当前原点错误平移。预热明确无预测，不用零点/上一帧伪造。

预测点内部的时间间隔尚未完成验证，dt_s保持null，不把控制器的速度系数当作标签时间证明；不逐点匹配未来真值，不计算ADE/FDE。源帧年龄与点间时间是不同概念。蓝色为记录历史、黄色为记录未来，绿色为规划分支的空间对照。

旧数据没有契约不叠加。开发中的spatial/1错误假定共同车中心，现拒绝；缺少实际生成anchor的早期spatial/2也拒绝。原始失败样本保留，不回写成通过。
