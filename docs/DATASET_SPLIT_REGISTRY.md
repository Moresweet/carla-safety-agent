## 使用流程

1. 明确指定关联场景组，使用 `tools/split_capture_datasets.py` 的 `--dataset-root` 创建带录制元数据证据的划分。不能以地图或模型名自动代替场景关联关系。
2. 显式登记已批准的文件：

```bash
PYTHONPATH=src python3 tools/register_dataset_split.py /absolute/path/approved-split.json
```

默认读取 `.runtime/generated-scenarios`，保存不可变副本到 `data/dataset-splits/<规范化内容 SHA256>.json`。登记前重新校验划分、最终录制状态、时间索引与元数据哈希；拒绝空划分或未验证划分。原划分和录制不移动、不修改。相同内容重复登记复用现有副本，不覆盖现有文件。

3. `tools/inventory_capture_storage.py` 自动扫描已登记文件，同时仍支持重复的 `--split` 参数检查未登记的显式路径。每条录制的 `split_referenced_by` 合并两类引用，另存登记范围摘要。
4. 历史替代基线清理工具在生成清理计划前、每次删除前检查已登记引用。仍被引用或扫描不完整时拒绝删除。本轮只修改保护逻辑和使用临时测试数据验证，**没有运行删除命令**。

## 保守处理与验收边界

- 先写独占临时文件并 fsync，再用不覆盖的硬链接发布最终名称；不覆盖同名不同内容文件。若留下 partial 文件，扫描标记不完整。
- 文件内容与名称哈希不符时，保留已解析出的引用，并报告不完整。损坏、链接、目录及超过 500 项扫描上限均不能解释为没有引用。
- 缺少登记目录仅表示本项目没有登记副本，不表示外部不存在划分。未登记的外部文件仍需显式提供和人工核对。
- 登记仅验证元数据与时间索引，不验证全部原始传感器字节、不证明场景组相互独立。登记之后原数据变化仍需使用 `tools/verify_dataset_split.py` 复核。
- 普通盘点与删除之间不是全局原子事务；上述共享锁仅关闭已登记划分的并发窗口。项目/外部依赖及其他保留规则仍然有效，单项无引用从不代表可以删除。
- 现有网页盘点尚未显示登记划分引用；需继续接入并做可视化验收。阶段 S4 未整体完成。
