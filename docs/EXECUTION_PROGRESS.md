# 执行阶段与实景保留倒计时

端到端测试页和自然语言计划确认区显示当前会话的原生工作进程阶段：连接、地图加载、创建对象、加载模型、传感器预热、闭环推理、保留实景、清理、等待会话确认。

原生短测试完成推理后默认保留实景 60 秒。此时不再推进新推理，但进程及会话仍占用仿真；倒计时单独显示，期限到达也必须等待实际退出清理。保持既有保留时长和停止操作，不因为显示进度而提前释放所有权。

## 可信边界

- 工作进程在自身阶段边界写 `data/experiments/<execution-id>/progress.json`，带 PID、Linux 启动 ticks、执行 ID、阶段、报告时间及可选步数/期限。不从日志关键字猜测。
- `/session/status` 只读取当前会话对应的报告；执行与进程身份不符、未知阶段、越界步数、非有限时间、超大文件、重复 JSON 键或链接路径不展示成有效进度。
- 报告是最近观察，不是心跳。报告较旧可能是加载或长推理，也可能异常；仅凭年龄不能断言卡死或自动停止。读取失败明确提示状态未知，不据此重启任务。
- 已完成仿真步数不是总运行时间百分比；提前碰撞终止时可能少于计划步数。阶段 `worker_finished` 不是最终成功，仍需父进程会话结论与资源检查。
- 旧执行、独立采集、规则运行及未接此报告的其他后端显示“尚无可验证报告”，不显示前一次模型的进度。
- 报告写失败只停用辅助报告并打印错误，不改变模型调用、控制输出或执行清理。这是展示文件，不是资源所有权账本，不用于恢复授权。
- 与会话日志分开写，不宣称跨文件/引擎事务。正在执行时不热修改原生工作进程代码。

## 验证入口

`tests/test_execution_progress.py` 覆盖身份、时间、步数、缺文件、链接、终态、倒计时、写盘失败及旧后端。
真实测试入口 `tools/regression_execution_progress.py --model vad --node /absolute/path/to/node` 会启动明确选择的真实模型、观察实际阶段、在保留实景阶段打开隔离浏览器验证倒计时，随后验证原始采集与退出清理。运行数据留在 `runs/validation/`，不提交 Git。
